# Instructor Guide

## Preparation

- Verify that learners have GitHub accounts and organization access.
- Enable GitHub Actions on the course organization.
- Decide whether learners share one organization or use individual repositories.
- Provide a repository with main branch protection enabled.
- Review feature availability and plan limits before the course.
- Have a browser, Git, Python, and GitHub CLI available.

## Delivery principles

- Demonstrate one workflow, then let learners repeat it.
- Pause after each major concept for a scenario discussion.
- Use failure cases: a blocked pull request, broken workflow, missing secret, or failing test.
- Separate GitHub features from Git concepts in the explanation.
- Ask learners to explain expected security and permission behavior before configuration.

## Debrief prompts

1. Which controls belong in repository settings, organization settings, or code?
2. How would you prove that a change is safe before deployment?
3. What is the smallest permission that a workflow should receive?
4. How would you respond to an exposed secret?
5. What evidence should a release provide?
